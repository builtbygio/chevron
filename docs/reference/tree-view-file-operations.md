# Tree-view file operations

Add file, add folder, rename, duplicate, delete. All of them were broken at
once, in two different ways, and neither showed up in a test because nothing
constructs a dialog outside a running editor.

## `this` before `super()`

Every dialog threw the moment it was built:

```
Must call super constructor in derived class before accessing 'this'
```

CoffeeScript let a subclass constructor assign its fields and call the parent
afterwards. Decaffeinate carried the shape over unchanged — the header of each
of these files still says `DS002: Fix invalid constructor` — and as real ES6
classes they cannot run at all.

The fix is mechanical: work the `super()` arguments out in locals, call
`super()`, assign the fields after. A scan of `src/` and `packages/` found
exactly three, all of them here:

| File | Field assigned too early |
|------|--------------------------|
| `add-dialog.ts` | `this.isCreatingFile` |
| `copy-dialog.ts` | `this.initialPath` |
| `move-dialog.ts` | `this.initialPath` |

`script/ci/derived-constructor-super.test.js` scans for the shape across the
repo. It blanks comments and string literals before judging — the first
version flagged its own explanatory comment.

## The shim has to be fs-plus

`fs-via-main.ts` routes the tree-view's disk work to the main process so the
renderer needs no `fs`. What it stands in for is **fs-plus**, and fs-plus does
more than node's `fs` in two places:

```js
writeFileSync: function(filePath, content, options) {
  mkdirp.sync(path.dirname(filePath));
  ...
```

Dropping that broke Add File for any path naming a folder that did not exist
yet — the ordinary way to make one from that dialog — with an ENOENT in the
dialog's error line. `copySync` had lost the same thing.

`script/ci/tree-view-fs-shim.test.js` pins both, and pins the fs-plus
behaviour itself rather than a belief about it: if a future fs-plus stops
creating the parent, the reason for the shim's mkdirp goes with it and the
test says so.

Its header once claimed it was generated by `script/lib/write-tree-view-fs-shim.js`.
That script no longer exists; the file is maintained by hand.

## What is covered

| | |
|--|--|
| `script/ci/derived-constructor-super.test.js` | the constructor shape, repo-wide |
| `script/ci/tree-view-fs-shim.test.js` | the shim creates the destination directory, for writes and copies |

Driving the real dialogs in the packaged app is what found both, and it is
still the only thing that exercises them end to end: add file, add folder,
rename and duplicate each doing what they say, delete removing a file and a
populated directory, and the project root refused with its own message.
